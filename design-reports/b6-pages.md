## 0. Honesty corrections to the mission brief (read first)

- **LibraryView has NO interactive study tools.** There are no flashcards-with-shuffle, no difficulty levels, no progress trackers anywhere in `web/src`. `grep -ri "shuffle|difficulty" web/src/` → zero hits in components (only `demoData.js`/`mock.js` strings and generation-type labels). `LibraryView.jsx` renders **read-only previews** (`My Materials` cards echo card Q/A and quiz options) and the Files/Saved/Calendar tabs are **100% demo data** (`demoData.js`, gated by `demoEnabled()`). Flashcards/quiz/difficulty/shuffle/progress must be treated as NEW functionality in the regeneration spec (Stitch `study_tools_v3_1/2` screens are the design source).
- **DataLakeView is a submission form, not a browse/export surface.** It submits text/files for micro-credit valuation and lists submission history with a plain table. The user's scraped/exportable data actually lives in `AssignmentHistoryView` (Export All JSON + per-assignment export) and `SettingsSections.jsx` (≈L783 "Export your data" + Data Lake toggle at L775). Spec should keep DataLake as contribution+earnings and note the browse/export gap as a separate concern.
- **InsightsView is a 44-line tab wrapper** merging `AnalyticsDashboard` (overview) + `IntelligenceView` (progress/recommendations). The real chart surface is `AnalyticsDashboard.jsx` — **one chart type only**: a single `AreaChart` ("Telemetry Activity (Last 30 Days)"). Restyle chart impls only.
- **ExtensionInstallView believes Firefox/Safari are working install paths** but they use the SAME zip (development-runtime loaders); the live-asset path is the hardcoded Chrome Web Store listing `https://chromewebstore.google.com/detail/helpotron-academic-compan/nlbbjhgmdmjmlgojeiblkhfmmnlmfmjk`; `v2.5.1` hero badge is hardcoded while the zip fallback label uses live `getExtensionVersion()` (fallback `2.0.1` on error).

## 1. Global: two visual languages, no shared primitives

The app is split into **two unreconciled systems**:

1. **M3-token pages** — Insights overview (AnalyticsDashboard), AssignmentHistoryView, DataLakeView, AssignmentDumpView, LibraryView, NotFound. All `bg-surface-container-lowest rounded-3xl border-outline-variant/30 shadow-sm` cards, `font-title-md text-title-md` headings, sem-color chips.
2. **Stitch dark-glass pages** — IntelligenceView (progress/recommendations), CreditsView's entire body (`CreditsPricingDashboard`, `ReferralSection`, `CreditLeaderboard`), `ExtensionInstallView`, and the `ui/os.jsx` primitives (`Badge`, `EmptyState`, `Tabs::segmented`, `StatCard`, `Timeline`, `DataTable` — all `clean-card`, `bg-white/5`, `text-slate-*`, `var(--text-muted)`). These hardcode `bg-white/4`, `border-white/10`, `text-slate-400`, `var(--accent)`, `glow-accent`, `surface-glass-strong` instead of `--st-*` tokens.

**Buttons: three competing definitions.**
- `components/Button.jsx` (used by AssignmentHistoryView): token vars, `min-h-[44px]`, `focus-visible` ring, `aria-busy`, variants primary/secondary/ghost/danger/aurora.
- `components/ui/Button.jsx` (used by ReferralSection): `bg-blue-600` brand blue, rounded-xl, `loader` prop `isLoading`, its own size table (36/44/48px).
- **Raw `<button>` everywhere else**: AssignmentDumpView (≈20 buttons), ExtensionInstallView (all), NotFound (both), AssignmentHistoryView (tab pill buttons, icon buttons = hand-rolled 44px). Repeat of the full class string per instance.

**Tabs: three different idioms** — (a) `ui/os.jsx` `Tabs` → `.segmented .seg-item` pilled bar (InsightsView, LibraryView); (b) single-tab pill pair `px-4 py-2 rounded-xl bg-primary text-on-primary` with `aria-pressed` (AssignmentHistoryView ledger/archived); (c) segmented control `bg-surface-container-low p-1 rounded-2xl` with `role=tablist`, selected = `bg-surface-container-lowest text-primary` (CreditsView). Also AssignmentDumpView has its own 4-chip `p-1 rounded-2xl bg-surface-container-low` filter group `aria-pressed` (close to (c) but different radius/border).

**Empty states: four shapes** — M3 bordered `rounded-3xl p-12` card with centered icon+title+body (History ledger & archived, Dump "No items", Analytics "No study activity yet"); `ui/os` `EmptyState` panel with emoji icon (Library x3 + calendar); plain text lines (DataLake history, BillingView transactions, ui/os DataTable "No rows."); and **no empty state at all** — chart/ROI cards simply unrender. Gap: Library Files tab empty state's `window.location.hash=''` action ("Upload materials") is a no-op (comment says `{/* dump view */}`).

**Status/subject chips duplicated** — `getSubjectChipStyle` + `getHistoryStatusChip` are private to `AssignmentHistoryView.jsx` (L21-70, regex subject palettes), while AssignmentDumpView chips and DataLake chips and CreditLeaderboard chips each re-implement near-identical amber/primary pill logic inline. Amber used as "warning" is inconsistent: `text-amber-300` + `bg-amber-500/15` (DataLake notice, dump unmatched, history not used, calendar draft_ready) vs `--st-error` (overdue) vs `--st-sem-amber` (history subject chips).
